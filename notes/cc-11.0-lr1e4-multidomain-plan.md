# cc-11.0 — lr 1e-4 Stage-2 + rollouts across airline / finance / insurance

Plan, design rationale, and running results for the multi-domain repeat of the retail
lr 1e-4 experiment. Started 2026-09-01. **Status: PLANNED / RUNNING — results appended
below as they land.**

---

## Why this experiment exists

Retail produced a result that invalidates the metric we had been selecting checkpoints on.

Two checkpoints from the SAME training run (retail `thoughts_policy`, `sft_flat`, AdamW
lr 1e-3), rolled out on the same 42 held-out tau2 tasks with an identical harness:

| | eval action-PPL | user turns/ep | task completion |
|---|---|---|---|
| batch 20 | 1.7828 | 3.61 | **11.9%** |
| batch 35 (`step_best`, PPL-optimal) | **1.7150** (better) | 2.05 | **0.0%** |

The SFT objective *improved* while the ability to do the task went to zero. This is a
within-run comparison — optimizer, corpus, batching, task set and harness all fixed — so
it is not a cross-generation confound. Over this stretch **eval PPL is anti-correlated
with task completion**, and `step_best` reliably selects the worse policy.

Mechanism (measured, not inferred): episode length is unchanged (~13 assistant turns) but
**user participation halves**. The policy stops asking the user and spends its turns
querying tools, sometimes brute-forcing arguments (`emma_kim_601/640/691`). In tau2 the
user holds the reservation IDs and preferences, so a policy that stops asking cannot
finish. Across every checkpoint measured, user-turns/ep is monotone with completion:

| checkpoint | user turns/ep | completion |
|---|---|---|
| SGD 3e-3 `step_best` | 4.53 | 21.4% |
| AdamW 1e-3 `step_0020` | 3.61 | 11.9% |
| AdamW 1e-3 `step_best` | 2.05 | 0.0% |

lr 1e-4 on retail then showed the SFT objective is **not** the thing being traded away:
best PPL was unchanged (`actions_only` 1.7538 vs 1.7670; `expert_thoughts` 1.6373 vs
1.6409) while **median |B@A| fell ~5x** at matched batch counts. So a 10x LR cut buys a
large reduction in weight drift for free. Whether that restores rollout behaviour is what
the retail snapshot ladder is testing, and what this multi-domain run generalises.

## Design

**Arms (3, not 4).** `actions_only`, `expert_thoughts_all`, `thoughts_policy_adamw30`.
Plain `expert_thoughts` is dropped: ~50% of its targets are bare `<tool_call>`, which
teaches the model not to think (it reasoned on 5.6% of retail rollout turns vs 19.7% for
`thoughts_policy`). `expert_thoughts_all` filters targets to reasoning-bearing turns —
per-domain retention measured 2026-09-01:

| domain | kept / total train steps |
|---|---|
| airline | 119/221 (54%) |
| finance | 209/698 (30%) |
| insurance | 531/819 (65%) |

**Config.** `sft_flat`, AdamW **lr 1e-4**, `num_batches 200`, `steps_per_batch 32`,
`eval_every 5`, `patience 6`, `save_every 10`, hide-observations, r8/a16. Identical to the
retail lr 1e-4 sweep so results are directly comparable.

**Checkpoints.** `save_every 10` gives a fine ladder because the useful checkpoint is
early and under-trained. `step_best` (PPL) is retained but is explicitly **not** the
selection criterion — see above.

**Selection criteria tracked** (`scripts/report_checkpoint_grid.py`): eval action-PPL,
eval action-accuracy, max |B@A|, median |B@A|. Median movement is the statistic that
separated the conversational SGD checkpoint (4.7e-05) from the collapsed AdamW ones
(1.5-2.2e-03) — but it is NOT a reliable predictor on its own (lr1e-3 `step_0020` sat 31x
above SGD and still conversed), so rollout behaviour remains the ground truth.

**Rollouts.** Per domain, on a snapshot ladder rather than only `step_best`, measuring
**user-turns/episode** as the primary read (hundreds of turns, far better powered than a
42-task completion count whose Wilson CIs span 5-25%).

## Known risks going in

1. **Insurance rollouts may not be runnable.** The gym exists
   (`act_prm/snorkel_insurance_gym.yaml`) but has never been used for a rollout eval, and
   the `rl_eval` uid -> task-index mapping is an open TODO. Airline uses the tau2 gym
   (`run_sft_rollout_eval.sh`, proven); finance uses `run_finance_rollout.sh` (proven, but
   needs `MAX_TURNS=24` — at the env default of 12 every arm scored 0/10 because the
   policy never reached `respond_user`).
2. **Airline overfits fastest** (21 train trajectories, so 200x32 steps is many epochs).
   Expect early stopping to fire well before b200.
3. **Airline's Act-PRM corpus has 239 train steps vs the base pool's 221** — the
   epoch-wrap duplicate-trajectory artifact. ~8% more data for that arm; not blocking but
   it is not a perfectly matched comparison.
4. **n=42/18 single rollouts are noisy.** The same checkpoint scored 11.9% at n=42 and
   15.1% at n=126. Completion differences of 1-3 tasks are not interpretable.
