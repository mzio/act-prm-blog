# Act-PRM Experiments TODO

We are carrying out the PyTorch-based experiments for the Act-PRM blog.

In particular we want to focus on doing (1) Act-PRM thought generation from huggingface models (using LoRA), (2) SFT'ing the HF models using either (a) expert action-only trajectories, (b) Act-PRM generated thought-action trajectories, (c) expert thought-action trajectories, and (3) using these SFT'd checkpoints to then further train with RL against the RL environments for full RL-based task completion.


## Plan

We will default to using HuggingFace Qwen3-4b-Instruct-2507 and do our training on the Tau2 airline and retail environments. 

We carry out the above in 3 stages.

### Stage 1: Thought Generation
Given existing logs of expert thought-action datasets, we will first train a model via Act-PRM to generate thoughts that could have been emitted from action-only datasets. The thought-action datasets serve as an oracle reference, so we prepare them for this stage by just using the expert actions.

We should make sure that we follow the predetermined splits, e.g., we have a held-out set of test tasks from the logs that we only use for RL evaluation in Stage 3. Then among the other tasks (and their logs), we can split these into train and eval tasks. For each Stage 1 and Stage 3, we will train the models on these train tasks, and then evaluate on these eval tasks. 

For Act-PRM, we'll want to do types of EM-scoring:  
1. "on-policy": We use the currently trained model (e.g., with the LoRAs attached) to score the generated thoughts based on their next-ground-truth-action likelihood: p(action | state, generated_thought)  
2. "base": We use the base model (e.g., Qwen3-4B-Instruct-2507) to score. This can be done by detaching the current LoRA.  

After this finishes training (we can pick a number of total RL batches), we will generate thought-action complete SFT trajectories for all stage-1 train / eval samples, using the best checkpoint from Stage 1. 
- We should probably set this up simply as 1 SFT sample being (state, action), where we only supervise next-token prediction on the actions. 

### Stage 2: SFT  
After this SFT data collection, we'll train various models (from the original base checkpoints, e.g., Qwen3-4B-Instruct-2507 fresh) with different SFT datasets for comparison. These include:  
- Expert action-only  
- Act-PRM thought-action (base-score)
- Act-PRM thought-action (policy-score)  
- Expert thought-action  

While we will use these to initialize checkpoints for Stage 3 RL training, we can track offline SFT metrics. After every N SFT updates, we should run the models on all the eval samples, and compute metrics such as:  
1. action-token perplexity
2. action accuracy (e.g., for each token in the actions, does the model predict that next-token with the highest likelihood across all tokens in the vocab)  

We'll also want to run the SFT here (and for Stage 3) under 2 settings:  
1. Hide-observations: where we only show the `system_prompt`, first `user_message`, last tool result (or user message), and *all* prior assistant generations (e.g., thoughts + actions, or just actions) as the state, for the model to generate from  
2. Full-context: where we just show all prior messages as the state (like hide-observations, except including all prior user or tool messages  

### Stage 3: Env RL  
Then with the best checkpoints from Stage 2 (Early-stopping based on held-out sample eval perplexity), we should use them to initialize RL runs against the actual environments (e.g., Tau2 bench envs). 

For these, we'll use the Tau2 scoring, and default to judging completion and also using the user-model in tau2 with `claude_agent_sdk`. 

For these, we can RL either on all the train/eval tasks we had available before, and then every N RL batches evaluate on the initial test tasks. Or we can just train on the train tasks, do RL generation-based evaluation on the eval tasks, and pick the best one to do a final test task evaluation.
